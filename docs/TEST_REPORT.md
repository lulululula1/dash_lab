## 4. 검증 중 발견해 수정한 문제

1. 엑셀 오류 셀(`#DIV/0!`)이 숫자 열을 문자 열로 오판 → 오류 셀은 유형 판정에서 제외하고 해석 오류로만 집계
2. 작은 표에서 오타 1건으로 숫자 열이 문자 열로 판정 → 예외 값 1건까지 허용 규칙 추가
3. 탭이 백그라운드일 때 스캔이 멈춤(`requestAnimationFrame` 정지) → 타이머 기반으로 변경
4. React StrictMode에서 상세 패널 등장 애니메이션이 중간 상태로 남을 수 있음 → `fromTo` + `context.revert()`
5. 그라디언트 제목 글자가 보이지 않음(변환된 자식 요소와 `background-clip: text`) → 글자별 적용
6. 사용자 CSS가 Tailwind 유틸리티를 덮어씀(표 정렬, 드롭다운 위치) → `@layer components`로 이동
7. 추천 품질: `참가자수`가 대표 수치로 선택되지 않음, `비고` 열이 범주로 사용됨, 막대·도넛 기준 열이 뒤바뀜 → 규칙 보완 및 테스트 추가
8. 첫 화면 번들 1 MB → 관제실(ECharts) 지연 로딩으로 122 KB(gzip)

## 5. XLSX 호환성 보강 (사용자 보고: "xlsx 업로드 시 오류")

실제 엑셀 파일 50개(셀 내용은 출력하지 않고 성공 여부·구조만 확인)로 원인을 재현했습니다. 여러 시트 자체는 원인이 아니었습니다(시트 2~8개 파일 정상).

| 원인 | 파일 수 | 증상 (수정 전) |
| --- | --- | --- |
| XML 요소에 `x:` 네임스페이스 접두사 (.NET OpenXML SDK·자동 생성 도구 형식) | 11 | ExcelJS 열기 실패 → "XLSX 파일을 열 수 없습니다" |
| 차트·그림(drawing) 포함 | 1 | ExcelJS 내부 오류 → 같은 메시지 |
| 공유 문자열이 CDATA로 저장됨 (웹 시스템 '엑셀 다운로드') | 3 | 오류 없이 모든 문자열이 빈 값 → "데이터를 찾지 못했습니다" |
| 시트 파일명 대문자(`Sheet1.xml`) | 1 | 오류 없이 시트 0개 |
| 엑셀 임시 잠금 파일(`~$…`) | 4 | 손상 파일로 안내 |

조치: 값만 읽는 자체 XLSX 판독기(`src/engine/xlsxLite.ts`, fflate + DOMParser, 접두사 무관·CDATA·병합 셀 채우기·날짜 서식·1904 체계·숨김 시트 지원)를 기본 경로로 사용하고 ExcelJS는 대체 경로로 유지. 잠금 파일은 전용 안내. 결과: 50개 중 50개 열기 성공(헤더만 있는 1개는 "데이터 행 없음" 안내), 두 판독기 모두 성공한 파일에서 값 불일치 0건(ExcelJS가 값을 잃은 경우 제외). 일반 업로드에서 ExcelJS(256 KB gzip)를 내려받지 않게 됨.

## 6. 알려진 제한 사항

- 파싱·분석이 메인 스레드에서 실행되어, 수 MB 이상의 XLSX는 스캔 중 화면이 잠시 멈출 수 있습니다 (로드맵: Web Worker).
- 머리글 행·열 유형은 자동 판정만 지원하며 수동 수정 기능은 없습니다.
- UI 컴포넌트 자동 테스트(e2e)는 아직 없으며, 브라우저 검증은 위 시나리오를 수동 실행한 결과입니다.
- 웹 폰트는 Google Fonts에서 불러옵니다 (데이터 전송과 무관, 폰트 파일 요청만 발생).
